# 地图场馆发现用户旅程

## 权威边界

- 场馆名称、地址、排序、`booking_mode`、标记坐标、导航坐标与已核验交通均来自 `deploy/venue-directory.json`；Artifact 不引入新的 canonical contract fixture。
- 示意底图只表达已核验场馆之间的大致构图，不冒充或复制第三方地图瓦片。真实地图加载失败时，场馆目录仍是可用且诚实的主内容。
- `ONLINE` 与 `DIRECTORY_ONLY` 同时使用形状、标签和文案区分，不能只靠颜色。`DIRECTORY_ONLY` 永不显示订场、查看可订时段或任何 booking action。

## 历史基线：横向底部卡片

以下行为仅用于解释已冻结的历史参考图，不再作为新实现的权威交互：

1. 首页默认显示五个标记和横向滚动的底部卡片。
2. 卡片 sheet 使用旧的 `peek`、`half`、`expanded` 命名。
3. 选中卡片可能通过条件渲染操作区改变高度。

## 当前权威：可扩展纵向场馆目录

当前实现以 `docs/superpowers/specs/2026-08-06-scalable-map-venue-directory-design.md` 为权威：

1. 初始 `CITY` 状态显示“全部球场”，按平台 `sort_order` 稳定排序，不请求位置且不显示伪造距离。
2. 用户显式点按 48×48 px 准星定位按钮并授权后进入 `USER_LOCATION`；列表按距用户位置升序排列，显示“距你 …”。
3. 用户选择腾讯地图 POI 后进入 `POI`；POI 只作为搜索中心，列表仍只包含平台场馆，并显示“距<POI 名称> …”。
4. sheet 只使用 `collapsed`、`half`、`expanded` 三个 snap state；默认 `half`，其可见区域容纳两个完整的 116 px 条目。
5. 场馆使用纵向主滚动列表。每个条目固定 116 px 高并永久保留 44×44 px 尾部箭头槽位；选中只改变内描边、背景和地图焦点，不改变外部尺寸或相邻条目位置。
6. 条目主体只负责选择并聚焦；尾部箭头始终存在。`ONLINE` 显示“可在线预订”并进入可订时段，`DIRECTORY_ONLY` 显示“仅提供场馆信息”并进入详情。
7. 地图不显示常驻图例；标记形状、条目状态文字和业务动作共同表达状态语义，不能只靠颜色区分。

## 详情深链聚焦

1. 每个场馆详情都显示“在地图中查看”。
2. 该操作打开地图 route，并携带稳定的 venue slug/id。
3. 地图先按场馆标记坐标聚焦并打开对应卡片；深链聚焦不隐式请求用户位置。
4. 返回时回到原场馆详情，并保留用户先前的地图/card/sheet 状态。

## 用户位置：仅显式请求

1. 首屏不请求位置权限，也不把地图中心伪装成用户当前位置。
2. 只有用户点按定位按钮后才调用位置能力。
3. 用户拒绝后，保留五场馆浏览能力，解释权限用途，并提供“打开系统设置”和“继续浏览球场”。
4. 从拒绝态恢复时，再次点按定位按钮才重试；深链、重挂地图或普通刷新都不自动触发权限请求。

## 地图首载与渐进渲染

1. 地图实例首次挂载后等待第一个 `bindupdated`。
2. 目录成功后立即挂载地图、五个标记和场馆卡片，不设置基于时间的地图健康检查。
3. `bindupdated` 只表示某次渲染更新完成，不作为成功/失败判定；缺失回调时保持地图实例和卡片，允许原生底图继续完成渲染。
4. 场馆卡片始终可浏览和进入详情；运行时不再提供会误报的定时 pure-list fallback。
5. 重试不会请求用户位置，也不会把目录场馆升级成可在线预订。

## 加载、错误与资源预算

- 地图加载期间保留稳定容器，避免 sheet 跳动；错误信息必须给出恢复动作。
- 页面只保留一个地图实例、五个 marker 和当前可见卡片所需内容；原生 marker PNG 资产在后续实现任务提供，本 Artifact 仅使用 CSS/vector 形状。
- Artifact 阶段不使用业务 Fixture。后续前端若为预览引入临时 Fixture，须在真实目录加载与错误/重试集成通过后删除，生产包不得包含模拟场馆数据。
