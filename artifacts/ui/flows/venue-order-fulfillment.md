# 场馆订单履约流程

`allowed_actions` 是页面中所有业务的唯一按钮权限来源。客户端只投影服务器给出的
`can_check_in`、`can_complete`、`can_refund`，不得根据时间、状态或本地猜测重新放行。

## 代表状态

1. `refund-confirm`：当 `can_refund=true` 时，从可退款订单打开全额退款确认层；原因必填。
2. `check-in`：`CHECK_IN` 成功后重新读取列表，订单转为已签到；结果不确定时保留原操作键并显示重试。
3. `complete`：已签到且服务结束的订单才展示完成服务；成功后重新读取列表。
4. `empty`：当天无订单，只保留日期切换，不伪造业务操作。
5. `read-error`：显示读取失败与真实重试按钮，不保留过期订单卡。

退款仅支持场地方原因的整单全额退款。当前切片不包含报表、搜索、部分退款、批量操作、扫码或客服工具。

视觉阶段的 Fixture 只模拟页面状态；视觉确认之后才接真实契约、鉴权与持久化，生产代码不得导入 Fixture。
