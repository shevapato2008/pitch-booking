# 三类用户平台整体切片路线图

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按依赖波次交付场馆、队长、散客和平台运营四个用户面的真实旅程，同时限制并行在制品。

**Architecture:** 微信小程序承载三种普通用户目的入口和业务旅程；FastAPI/PostgreSQL 提供身份、权限、库存、订单和球局权威状态；OSS 保存场馆媒体；后置的独立 Web 后台承载平台级加盟与认领审批。每个切片必须真实可部署、状态诚实且不含生产 Fixture 才算完成。

**Tech Stack:** 微信小程序 TypeScript/WXML/WXSS、FastAPI、SQLAlchemy、PostgreSQL、阿里云 OSS、DashScope、独立 Web 管理后台。

---

## 状态说明

- `已完成`：生产真实链路已经闭环并通过相应验收。
- `验收收口中`：实现已接入真实后端，仍有明确的设备验收或合并发布工作。
- `可用版本已交付 / 验收债延期`：生产能力已经实现并部署，可以继续后续 MVP 开发；明确列出的真实设备或数据库验收证据仍未通过，不等同于“已完成”。
- `下一项`：当前完成设计确认，随后进入实现。
- `待开发`：依赖前序切片，尚未开始生产实现。

### A3：场馆认领、新场馆加盟与平台审核 — 可用版本已交付 / CREATE 真机验收延期

普通小程序和独立 Web 后台共同组成一个完整垂直切片：

- [x] 小程序支持搜索并认领已有场馆，或提交尚未收录的新场馆加盟申请。
- [x] 新增独立申请数据和私有证明材料，不把未核验场馆提前写入公开 `venues`。
- [x] 创建申请在提交与批准两个边界分别执行去重检查；命中已有场馆时转入认领，不复制场馆。
- [x] 独立 Web 后台只接受平台级凭证，服务端校验 `PLATFORM_ADMIN` 或 `ONBOARDING_REVIEWER`；普通用户和场馆管理员均无权访问。
- [x] 审核人员可以查看证明、批准或拒绝申请，并记录操作者、时间和原因。
- [x] 批准已有场馆认领时只创建或激活目标 `venue_id` 的 `venue_memberships`。
- [x] 批准新场馆时在同一事务中创建 `is_listed=false` 的正式 `venues` 和首位管理员 `venue_memberships`。
- [x] 审核前、审核中和拒绝状态都诚实展示；任何申请提交都不能自动获得权限。

A3 前移到订单和球局切片之前。平台主动招商邀请与员工分级授权仍保留在后续扩展，不阻塞首个“用户申请—平台审核—获得权限”闭环。

截至 2026-08-18，生产数据库、私有 OSS、申请 API、小程序页面、平台审核后台和部署已经完成。真实 CLAIM 已在 iPhone 完成提交，经平台批准后核对数据库不变量通过：只产生目标场馆的一条有效可管理 membership，没有创建新场馆。

CREATE 的生产代码与部署同样存在，但根据用户 2026-08-18 的明确决定，其真实 iPhone 提交—平台批准—数据库不变量核对与对应设备验收暂缓。这项证据仍是已知验收债，不得记为通过，也不得将 A3 标记为“已完成”；恢复时只需补做一次受控 CREATE 真实链路及聚焦设备核对。

该延期债务不再阻塞 B1 MVP 开发。团队现在可以从可用版本继续补齐订单履约，并在后续迭代回收 CREATE 验收债。

- [ ] 实现 owner 取消与退款生产路由、小程序动作和权威状态展示。

## 依赖与并行边界

- A2 的小程序视觉预览与 A3 的独立 Web 审核预览文件互不重叠，可以并行；两者均须用户视觉确认后才进入契约和后端。
- A3 的申请后端与审核后端共享状态机和数据库事务，不并行修改同一模型；契约冻结后，小程序 HTTP 集成和 Web 后台 HTTP 集成可以并行。
- B1 的共享生命周期基础已冻结后，微信 Provider、owner 取消退款、场馆履约三条轨道可在各自文件边界内并行；它们只能消费共享模型、revision `0013`、Provider result enums 和公共 OpenAPI schemas，不得回写这些权威边界。
- B1 稳定后，B2 的前端 Artifact 与 B1 的非重叠验收可以并行；B2 后端不能绕过真实订单状态。
- C1 的前端视觉可在 B2 契约冻结后并行，真实申请后端必须等待 B2 发布模型稳定。
- D1 只在 A3 稳定后开始；它与 C 系列领域数据独立，但不阻塞当前加盟主链路。
- 每个切片继续遵循 Artifact/真实运行时预览、契约、后端集成、聚焦自动化、真机验收和删除 Fixture 的完成定义。
