# 三类用户平台整体切片路线图

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按依赖波次交付场馆、队长、散客和平台运营四个用户面的真实旅程，同时限制并行在制品。

**Architecture:** 微信小程序承载三种普通用户目的入口和业务旅程；FastAPI/PostgreSQL 提供身份、权限、库存、订单和球局权威状态；OSS 保存场馆媒体；后置的独立 Web 后台承载平台级加盟与认领审批。每个切片必须真实可部署、状态诚实且不含生产 Fixture 才算完成。

**Tech Stack:** 微信小程序 TypeScript/WXML/WXSS、FastAPI、SQLAlchemy、PostgreSQL、阿里云 OSS、DashScope、独立 Web 管理后台。

---

## 状态说明

- `已完成`：生产真实链路已经闭环并通过相应验收。
- `验收收口中`：实现已接入真实后端，仍有明确的设备验收或合并发布工作。
- `下一项`：当前完成设计确认，随后进入实现。
- `待开发`：依赖前序切片，尚未开始生产实现。

## 波次 A：当前基础与入口

### A0：可扩展地图目录 — 已完成

真实场馆目录、地图搜索、行政区筛选、聚合标记和列表已经形成生产旅程，不再使用百条目录 Fixture 作为验收结果。

### A1：场馆资料、物理场地和库存工作台 — 验收收口中

已接入微信身份、场馆 membership、PostgreSQL、OSS、内容审核、物理场地和单场地库存。剩余工作只关闭已发现的真机交互/视觉问题，完成生产构建、Fixture 泄漏检查、真机验收、合并和部署。

### A2：三种目的生产入口 — 下一项

- [ ] 将已确认的三入口视觉移入生产包并设为小程序启动页。
- [ ] “我要租赁场地”进入现有真实地图旅程。
- [ ] “我要找球踢”显示“即将开放”，不进入 Fixture 或虚假列表。
- [ ] 增加只读的“我的可管理场馆”接口，以服务端 membership 为权威。
- [ ] 一个授权场馆直接进入工作台；多个授权场馆进入选择页；工作台可切换场馆。
- [ ] 零个授权场馆显示真实加盟说明；平台后台切片完成前不伪装成已提交申请。
- [ ] 只做聚焦路由、权限分支、生产构建和一轮目标 iPhone viewport 验收。

A2 可以在不改变 A1 数据模型的前提下先实施；完成后立即回到 A1 做最终验收收口，避免同时展开后续球局切片。

## 波次 B：订单与组织者旅程

### B1：补齐订单履约 — 待开发

完成我的订单、取消退款、到场和完成状态，为公开球局取消联动和真实履约提供基础。

### B2：队长开放名额 — 待开发，依赖 B1

已支付队长从真实订单创建球局，发布公开详情和分享卡片；一个订单最多对应一个未取消球局。

## 波次 C：散客旅程

### C1：散客申请与队长审核 — 待开发，依赖 B2

完成找球局、详情、申请、队长接受或拒绝、候补、关键状态通知和“我的报名”。完成后将入口页“我要找球踢”从“即将开放”切换为真实旅程。

### C2：退出、到场与治理 — 待开发，依赖 C1

增加退出、订单取消联动、队长记录到场/爽约、举报和平台人工纠错；不引入综合信用分或散客平台内分账。

## 波次 D：场馆加盟与平台运营

### D1：场馆认领、新场馆加盟与平台管理后台 — 待开发，排在现有切片之后

普通小程序和独立后台共同组成一个完整切片：

- [ ] 小程序支持搜索并认领已有场馆，或提交尚未收录的新场馆加盟申请。
- [ ] 新增独立的加盟申请数据，不把未核验场馆提前写入公开 `venues`。
- [ ] 平台主动招商时可创建一次性邀请，由场地方微信登录接受并补充资料。
- [ ] 独立 Web 后台仅对平台级角色开放；隐藏按钮和前端路由不作为安全边界。
- [ ] 审核人员可以查看、核验、批准或拒绝申请，并记录操作者、时间和原因。
- [ ] 批准已有场馆认领时只创建或激活目标 `venue_id` 的 `venue_memberships`，不得复制 `venues`。
- [ ] 批准新场馆时在同一事务中创建 `venues` 和首位管理员 `venue_memberships`。
- [ ] 新场馆初始 `is_listed=false`；资料、场地、库存和内容审核完成后再公开。
- [ ] 已认证负责人可以邀请场馆员工，并按资料、场地和库存范围授权。

本切片只建设加盟、认领、邀请、审批和授权，不扩展经营报表、客服工单或综合运营后台。

## 依赖与并行边界

- A2 与 A1 最终验收可以在代码层面独立，但同一时刻只保留一个待发布集成分支；A2 完成后再合并收口 A1。
- B1 稳定后，B2 的前端 Artifact 与 B1 的非重叠验收可以并行；B2 后端不能绕过真实订单状态。
- C1 的前端视觉可在 B2 契约冻结后并行，真实申请后端必须等待 B2 发布模型稳定。
- D1 与 C 系列领域数据基本独立，技术上可并行；按当前产品优先级仍排在全部现有切片之后，避免平台后台扩大当前在制品。
- 每个切片继续遵循 Artifact/真实运行时预览、契约、后端集成、聚焦自动化、真机验收和删除 Fixture 的完成定义。
