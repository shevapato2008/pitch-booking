# 我的订单切片设计

日期：2026-08-18

状态：独立产品决策已通过；待 A3 关闭后进入视觉确认

上游路线图：[整体切片路线图](../plans/2026-08-16-overall-slice-roadmap.md)

## 1. 目标与旅程

本切片补齐租场用户在离开订单详情后重新找到自己订单的最小真实旅程：

`三目的入口 → 我要租赁场地 → 场馆地图 → 我的订单 → 订单列表 → 订单详情`

用户可以看到自己的订单，点击任一订单进入现有真实订单详情页，并在刷新后看到服务端权威状态。列表不创造新的订单状态，也不伪装尚未接通的取消、退款或履约能力。

本切片排在场馆入驻 A3 之后。A3 的真实 CLAIM/CREATE 验收、分支集成和关闭完成前，本期只允许完成产品决策、设计规格与实施计划；不得启动 Artifact、Fixture、OpenAPI、生产代码或部署。

## 2. 方案选择

### 方案 A：按时间倒序的单列列表（推荐）

- 不设筛选，最近订单优先；
- 每张卡片同时显示场馆、场地、时间、金额和真实状态；
- 页面层级最少，适合首个“找回订单”闭环。

### 方案 B：按状态分组

- 待处理订单更突出；
- 但会把支付确认、关闭中等投影状态复杂化，空分组也增加噪声。

### 方案 C：顶部状态标签页

- 订单多时查找更快；
- 当前数据量和状态能力不足以证明额外筛选、计数与分页复杂度的价值。

本期采用方案 A。状态筛选等有真实使用量后再单独评估。

## 3. 信息架构与入口

### 3.1 地图入口

在现有场馆地图搜索栏下方增加第二行，左侧为搜索中心说明，右侧为独立的“我的订单”胶囊按钮：

- 点击进入 `/pages/my-orders/index`；
- 触控区域不小于 88rpx；
- 使用线性订单图标，不使用 emoji；
- 右侧入口固定宽度，左侧搜索中心说明允许单行截断，长 POI 名不得与入口重叠；
- 不挤压场馆列表标题、筛选按钮或地图定位按钮；
- 入口渲染在场馆目录 loading/error 条件之外；加载场馆目录失败时仍可进入，因为订单列表不依赖场馆目录成功。

### 3.2 订单列表页

目标视口为 375×812。页面从上到下：

1. 原生导航栏标题“我的订单”；
2. 页面说明：“最近的预订”与“状态以服务端为准”；
3. 订单卡片单列列表，按 `created_at DESC, id DESC`；
4. 有下一页时显示真实“加载更多”按钮；
5. 列表支持小程序原生下拉刷新；
6. 底部尊重安全区，不设置遮挡卡片的固定操作栏。

订单卡片整体是一个可访问的按钮，点击进入：

`/pages/order-detail/index?order_id=<uuid>`

卡片显示：

- 场馆名称；
- 物理场地名称；
- 上海时区的日期和起止时间；
- 人民币金额；
- 状态标题和一行诚实说明。

不在列表暴露联系人姓名、手机号、详细地址或支付内部字段。

## 4. 真实状态语义

只呈现后端已有的订单状态与既有投影字段：

| 服务端状态/投影 | 列表标题 | 列表说明 |
| --- | --- | --- |
| `PENDING_PAYMENT` | 待支付 | 请在订单关闭前完成支付 |
| `payment_confirming=true` | 支付确认中 | 结果以服务端确认为准 |
| `closing_payment=true` | 正在关闭 | 正在确认订单与场地状态 |
| `CONFIRMED` | 预订成功 | 场地已为你预订 |
| `EXPIRED` | 已过期 | 该订单已关闭 |
| `PAYMENT_EXCEPTION` | 支付待确认 | 请进入详情重新查询 |

同一订单只能显示一个优先级最高的投影状态：`PAYMENT_EXCEPTION`、正在关闭、支付确认中、已确认、已过期、待支付。`closing_payment=true` 必须遮蔽同时存在的 `payment_confirming=true`，与既有到期查单/关单语义一致。客户端不得根据本地时钟自行把订单改成已过期或已确认。

## 5. 页面状态与按钮行为

- `LOADING`：显示三张稳定骨架卡，不显示可点击的假订单；
- `READY`：订单卡片均可进入对应详情；
- `EMPTY`：显示“还没有订单”，真实按钮“去选场地”；前一页是地图时调用 `navigateBack`，否则 `reLaunch` 到 `/pages/venue-map/index`；
- `ERROR`：显示“订单暂时无法加载”，真实按钮“重新加载”只重试列表请求；
- `REFRESHING`：保留现有列表，顶部原生刷新状态结束后替换第一页；
- `LOADING_MORE`：保留已有列表并禁用重复加载；
- `LOAD_MORE_ERROR`：保留已有列表，按钮改为“重试加载更多”；
- `END`：不再显示加载按钮，可显示弱提示“已经到底了”。

所有异步请求使用 generation/revision 防止下拉刷新、分页与页面卸载后的旧响应覆盖新状态。401 只允许沿用现有一次微信重新登录后重试；仍失败则显示可重试错误，不清空为“没有订单”。

## 6. 视觉系统

复用已经确认的产品设计系统，不采用工具建议的琥珀色新主题：

- 页面背景 `#F8FAFC`；
- 表面 `#FFFFFF`；
- 主文字 `#10243E`；
- 次要文字优先 `#526479` / `#64748B`；
- 边框 `#DBE5EC`；
- 可信蓝 `#0284C7`，深蓝交互文字 `#0369A1`；
- 成功绿 `#047857`；
- 错误红 `#C42525`；
- 系统字体、4/8px 间距节奏、44pt 最小触控区域。

订单卡使用白色表面、轻边框、28–32rpx 圆角。状态不能只靠颜色：必须同时显示文字。按钮文字使用明确的 flex 双轴居中，固定底部安全区不得遮挡内容。

## 7. HTTP 契约

新增：

`GET /api/v1/orders?limit=20&cursor=<opaque>`

要求业务会话 `Authorization: Bearer <session_token>`。普通用户只能看到自己的订单。

闭合响应：

```json
{
  "orders": [
    {
      "id": "uuid",
      "order_number": "PB202608180001",
      "status": "PENDING_PAYMENT",
      "venue": {"id": "uuid", "name": "天津奥体足球场"},
      "pitch": {"id": "uuid", "name": "七人制 A 场"},
      "starts_at": "2026-08-20T11:00:00+08:00",
      "ends_at": "2026-08-20T12:00:00+08:00",
      "price_cents": 36000,
      "currency": "CNY",
      "created_at": "2026-08-18T09:30:00+08:00",
      "expires_at": "2026-08-18T09:40:00+08:00",
      "payment_confirming": false,
      "closing_payment": false
    }
  ],
  "next_cursor": null
}
```

规则：

- `limit` 默认 20、最大 50；
- 游标是不透明、稳定的 `(created_at, id)` 倒序游标，不返回总数；
- 后端查询必须限定 `orders.user_id = current_user.id`；
- 列表不返回联系人和完整场馆地址；
- 对到期的待支付订单复用现有过期服务；存在未终结支付、尚不能安全释放时返回 `closing_payment=true`，不得虚构已释放；
- 数据库查询、行锁或事务提交失败时整次请求返回 `503 SERVICE_UNAVAILABLE`，不得降级成“正在关闭”；
- 401、422 和数据库不可用使用现有错误信封；数据库不可用明确返回 503。

本切片不新增表、不新增订单状态、不修改支付事务。

## 8. 前端与 Fixture 边界

视觉确认阶段只在 development 包加入：

- `/dev/pages/my-orders/index`；
- 集中的 development-only 订单列表 Fixture；
- loading、ready、empty、error、load-more-error 五个可切换预览状态。

Fixture 不得被 production composition、生产 `app.json` 或生产构建复制。视觉确认后，生产页接真实 HTTP data source；Fixture 删除条件是生产列表服务、分页、重试、详情跳转均通过聚焦测试与真机验收。

## 9. 验收标准

视觉阶段：

- 375×812 同尺寸参考图、实现图、并排图和 50% 叠加/差异图完成自审；
- 地图入口、订单卡、重试、去选场地、加载更多均有真实 Fixture 行为；
- 按钮文字水平和垂直居中，状态徽标对齐，页面底部安全区无裁切。

生产阶段：

- 用户从地图进入“我的订单”，只能看到自己的真实订单；
- 离开现有订单详情后可从列表重新进入同一订单；
- 待支付订单过期后，下拉刷新显示服务端权威“已过期”或诚实“正在关闭”；
- 分页不会重复、漏页或被乱序响应污染；
- production 包不含 Fixture；
- A3 验收关闭后再部署并生成真机二维码。

## 10. 明确不做

- 订单筛选、搜索、状态计数；
- 用户主动取消；
- 退款；
- 到场核销、履约完成和评价；
- 真实微信支付 Provider；
- 新数据库结构或运营后台。
