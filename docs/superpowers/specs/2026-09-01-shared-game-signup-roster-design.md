# 分享球局报名接龙设计

## 目标

队长把已发布球局以微信卡片分享到群聊。用户打开现有“球局详情”即可查看公开报名进度并直接报名；不新建重复详情页。

## 已确认规则

- 名单仅登录后可见；匿名访问只显示正式报名数和候补数。
- 用户第一次报名时主动选择头像、确认昵称；资料以后复用并可更新。资料是用户选择的公开资料，不宣称为微信认证身份。
- 有公开名额时直接加入正式名单；公开名额已满时按报名时间进入候补队列。
- 正式成员退出或被队长删除后，按 FIFO 自动转正第一位候补；同时释放多个名额时依次转正。
- 队员可撤销自己的正式报名或候补，并可再次报名；再次报名按当时容量进入正式名单或候补队尾。
- 队长可删除正式成员或候补。被队长删除者不能重新报名，直到队长明确解除限制；解除后仍需该用户自己重新报名。
- 所有登录用户均可查看正式和候补名单中的头像、昵称；候补显示顺位；任何共享名单都不显示位置、备注、手机号、OpenID、内部用户 ID、报名时间或管理字段。
- 人数文案分开表达：`公开报名 X / open_spots` 与 `计划 total_players 人，其中固定队员 fixed_players 人`。固定队员当前只有计数，不混入接龙名单。

## 页面结构

沿用 `pages/captain-game-public`：

1. 原有真实订场确认与球局摘要。
2. 公开报名进度卡：正式人数/公开名额、候补人数、计划总人数与固定队员数。
3. 正式名单：头像、昵称；登录后展示人员，匿名展示登录提示。
4. 候补名单：顺位、头像、昵称；同样遵守登录可见。
5. 当前用户状态卡：可报名、已加入、候补第 N 位、已撤销、被队长移除。
6. 固定安全区底栏：`立即报名`、`加入候补`、`撤销报名`或对应禁用状态。
7. 队长在相同名单行看到删除操作；被移除名单/状态中提供“允许重新报名”。所有破坏性操作二次确认。

首次报名且资料不完整时，底部弹层使用 `button open-type="chooseAvatar"` 与 `input type="nickname"` 完成公开资料确认，资料保存成功后再提交报名。任一步失败都保留用户输入并提供真实重试。

## 后端与契约

- `User` 保存最小公开资料：昵称、头像对象 key、更新时间。
- 头像临时文件上传到受控对象存储；服务端只保存对象 key，不接受任意远程 URL。
- 现有注册上下文增加正式数、候补数及两份公开白名单投影。匿名投影的名单为 `null`，已登录投影返回头像昵称，候补额外返回顺位。
- 报名事务锁定球局容量：小于 `open_spots` 写入 `JOINED`，否则分配单调递增的候补序号并写入 `WAITLISTED`。
- 撤销/移除正式成员的事务在释放名额后复用现有 FIFO 提升逻辑。
- 自撤记录可被同一用户重新激活；队长移除记录带重报限制。队长解除限制只恢复报名资格，不自动加入。
- 名单响应使用 `Cache-Control: private, no-store` 与 `Vary: Authorization`；头像资源可独立缓存。

## 验收重点

- 公开名额未满直接加入，已满进入正确候补顺位。
- 撤销或队长删除后第一候补原子转正；候补顺位连续且不可手动调整。
- 自撤可重报；队长移除在解除限制前不能重报。
- 匿名永不收到姓名头像；登录用户只收到公开字段，位置始终不出现在共享名单。
- 所有按钮有真实端到端行为；失败和未知结果不显示假成功。
- iOS 与 Android 目标尺寸下，头像、顺位、按钮、状态徽标对齐，底栏不遮挡滚动内容并避开安全区。
