# 足球场预订小程序：可扩展地图场馆目录设计

**日期：** 2026-08-06

**状态：** 用户已确认视觉方向；独立规格审查已通过，待用户确认书面规格

**基线：** `docs/superpowers/specs/2026-07-30-map-venue-discovery-design.md`

**目标视口：** 微信小程序真机 390 px 宽度（同时回归 375 px）

## 1. 背景与目标

当前地图页使用横向场馆卡片承载场馆浏览。这个模式在五家场馆的验证阶段可用，但计划收录超过 50 家场馆后，会出现以下问题：

- 横向滑动无法建立总量感，也不适合快速查找第十家以后的场馆；
- 选中卡片后才渲染主操作，导致卡片高度变化和页面跳动；
- 文字“附近”被放入圆形定位按钮，图形语义和视觉比例不协调；
- 搜索只过滤平台场馆，无法把用户熟悉的地标、车站或地址作为新的搜索中心；
- 全城目录、当前位置附近与指定 POI 附近三种任务没有形成清晰状态。

本切片把地图页调整为“地图 + 可展开纵向场馆目录”。默认任务是浏览全城平台场馆，同时提供两个同等重要的入口：

1. 用户主动授权后，以当前位置为中心查看平台场馆并显示距离；
2. 搜索任意腾讯地图 POI，选择后以该 POI 为中心查看平台场馆并显示距离。

腾讯地图 POI 只用于确定搜索中心，不成为平台场馆目录的数据源。页面始终只展示平台已经收录的场馆。

## 2. 已确认决定

- 未来规模按 50 家以上设计。
- 初始状态浏览全城场馆目录，不自动请求用户位置。
- 横向滑动卡片不再作为主要场馆导航。
- 底部场馆区域改为可展开的纵向列表。
- 每个场馆条目使用固定高度；选中只改变内描边、背景和地图焦点，不改变外部尺寸。
- “附近”文字圆形按钮改为独立的定位准星图标按钮。
- 搜索栏既可匹配平台场馆，也可搜索腾讯地图提供的任意 POI。
- 选择腾讯 POI 后，页面只对平台已收录场馆重新计算距离和排序，不导入腾讯 POI 中的球场。
- `ONLINE` 与 `DIRECTORY_ONLY` 继续保持诚实边界，不能只靠颜色区分。

## 3. 信息架构

### 3.1 页面恒定区域

页面从上到下包含：

1. 微信原生导航栏；
2. 地图；
3. 地图上的搜索栏与定位按钮；
4. 当前搜索中心提示；
5. 可拖动底部 sheet；
6. sheet 内的标题、筛选项和纵向场馆列表。

地图仍是空间理解工具，纵向列表成为浏览和比较 50+ 场馆的主要工具。

### 3.2 三种搜索中心状态

页面只有一个显式的 `searchCenter`：

- `CITY`：初始状态。标题为“全部球场”，按平台 `sort_order` 稳定排序，不显示伪造的用户距离；
- `USER_LOCATION`：用户点按定位按钮并授权成功后进入。标题为“附近球场”，按与当前位置的端内直线距离升序排列；
- `POI`：用户选择腾讯地图 POI 后进入。标题为“<POI 名称>附近”，按与 POI 坐标的端内直线距离升序排列。

附近模式不使用硬半径隐藏远处场馆。所有满足当前筛选条件的平台场馆仍可通过纵向列表访问，距离只用于排序和解释，避免在场馆密度不足的区域制造空结果。页面另设只用于文案解释的“附近阈值”，天津首期为 20 km；阈值内没有场馆时不能继续宣称远距离场馆位于附近。`USER_LOCATION` 标题改为“离你最近的已收录球场”，`POI` 标题改为“离<POI 名称>最近的已收录球场”，中心提示显示“附近暂无平台场馆”，列表继续展示全部平台场馆并按距离排序。该阈值不改变结果集合，也不进入后端查询契约。

任一时刻只有一个已提交搜索中心。成功进入 `USER_LOCATION` 时清除 `draftQuery`、已提交 POI 名称和 POI 中心标记，定位按钮进入 active。成功选择 POI 时清除草稿并关闭定位按钮 active；已经获得的用户位置可作为非中心参考点继续显示，但不得参与排序或距离文案。选择平台球场搜索结果只清除草稿、关闭建议面板并选择/聚焦该场馆，不改变进入搜索前的 `searchCenter`、排序或距离基准。

### 3.3 搜索与筛选不是同一件事

- 搜索决定当前中心，或直接定位一个已收录平台场馆；
- 筛选只缩小平台场馆集合；
- 排序由当前中心决定：`CITY` 使用平台排序，`USER_LOCATION` 和 `POI` 使用距离排序。

首期筛选项为：

- 综合/距离排序状态标签；
- 可在线预订；
- 行政区。

筛选控件的文案必须反映真实行为。例如附近模式下第一项显示“距离最近”，不能继续显示“综合排序”。行政区筛选不得从自由文本地址推断；Artifact Fixture 使用结构化 `districtCode`、`districtName`，视觉确认后再将等价字段纳入地图目录契约并由场馆内容清单提供。如果契约阶段决定不增加结构化行政区字段，则本切片必须删除行政区筛选，不能降级为字符串解析。

筛选后如果当前选中场馆仍在结果中，则保持选中；如果被排除，则清除选中并按当前结果集合重算视野，不自动选择第一项。零结果保留搜索中心和筛选条件，并提供“清除筛选”。

## 4. 核心交互

### 4.1 初始全城目录

1. 页面加载平台场馆目录并显示全城地图视野。
2. sheet 默认停在 `half` 状态，显示约两个完整场馆条目，提示可向上展开。
3. 用户可纵向滚动列表、点按地图标记或展开 sheet。
4. 展开态提高到不覆盖导航栏和安全区的位置，并容纳连续纵向滚动。
5. 收起地图时保留当前列表位置、筛选、选中场馆和搜索中心。
6. 只有把手和 sheet 标题区响应改变吸附位置的纵向拖动；列表内容区始终只滚动列表，不改变 sheet 高度。切换吸附位置不得重置列表 `scrollTop`。

### 4.2 当前定位附近

1. 右上定位控件为 48×48 px 等效触控区的圆角方形按钮，使用准星图标，不显示“附近”文字。
2. 首屏不请求权限；只有点按按钮后调用 `wx.getLocation({ type: "gcj02" })`。
3. 请求中按钮显示不改变尺寸的 loading 状态，并防止重复请求。
4. 成功后地图中心移动到用户位置，按钮进入浅蓝选中态，列表按距离升序排列并显示“距你 X km”。
5. 拒绝、系统关闭或失败时完整恢复发起定位前的搜索中心、目录排序、筛选、选中场馆和地图视野；只有从初始 `CITY` 发起时才表现为保留全城目录。沿用现有权限说明与恢复入口，不得把失败误报为地图失败。
6. 用户位置只在页面内存中使用，不上传、不持久化、不写日志。
7. 成功进入 `USER_LOCATION` 时，地图首先以用户位置为中心并使用邻域级缩放；用户位置标记必须位于当前 sheet 未遮挡的可见地图区域。随后点选场馆才聚焦该场馆。

### 4.3 腾讯地图 POI 搜索中心

1. 搜索栏占位文案为“搜索球场或地图地点”。
2. 输入时同时执行两类检索：
   - 本地匹配平台已收录场馆名称和地址；
   - 通过窄边界 `PoiSearchCapability` 请求腾讯位置服务地点建议。
3. 建议面板把“平台球场”和“地图地点”分组展示，不能把腾讯 POI 伪装成平台球场。
4. 平台球场结果包含业务状态；点按后选择该场馆、聚焦标记并滚动到对应列表项。
5. 腾讯 POI 结果显示 POI 名称和结构化地址；点按后设置 `searchCenter = POI`，在地图放置独立搜索中心标记，并将平台场馆按距该 POI 的距离排序。
6. 搜索框显示已选 POI 名称；中心提示显示“<POI 名称>附近 · 可更换搜索中心”。
7. 进入 `POI` 时，地图首先以 POI 为中心并使用邻域级缩放；POI 中心标记必须位于当前 sheet 未遮挡的可见地图区域。随后点选场馆才聚焦该场馆。
8. `draftQuery` 与已提交的 `searchCenter`、`selectedVenueId` 相互独立。输入期间只更新建议面板，不改变底层目录、排序或地图中心；只有选择平台场馆或 POI 后才提交。
9. 取消编辑恢复进入搜索前的完整状态。清除已提交 POI 才恢复 `CITY`；清除未提交草稿不得清空原有 `USER_LOCATION` 或 `POI`。键盘“搜索”在没有明确选择时保留建议并提示“请选择具体球场或地图地点”，不得猜测第一项。
10. 腾讯 POI 请求失败时，本地平台场馆搜索仍可用；错误文案明确说明“地图地点暂时无法搜索”，不能阻断全城目录。

建议请求至少输入 2 个非空字符后触发，并使用短防抖避免逐键请求。具体防抖值和腾讯 SDK/API 配额在实施计划中依据官方接口限制确定，不写入业务契约。

### 4.4 场馆列表与地图联动

- 列表项固定为 232 rpx 高（390 px 目标视口约 116 px），所有状态保留同样的内容槽位和 88 rpx × 88 rpx（约 44 px）尾部箭头槽位。
- 名称、地址各固定一行，类型/距离复用一行摘要槽位，并使用省略规则；不能因内容长短撑高条目。
- 选中态使用 `box-sizing: border-box` 和内描边/背景表达，不能增加边框占位或条件渲染额外高度。
- 点按条目主体只执行“选择并聚焦”；不会意外跳页。
- 每个条目始终显示同尺寸尾部箭头；在线场馆箭头进入“查看可订时段”，目录场馆箭头进入“查看详情”，并分别提供完整无障碍标签。不得使用暗示立即创建订单的“订场”。在线预订状态由条目状态文案表达，不通过扩大按钮或卡片表达。
- 点按地图标记时选择对应条目，并把它滚动到纵向列表的可见区域；sheet 高度不因此改变。
- 点按列表条目时聚焦对应标记；地图视野改变但列表高度和滚动位置保持稳定。
- `ONLINE` 标记和条目显示“可在线预订”；`DIRECTORY_ONLY` 显示“仅提供场馆信息”。地图标记继续使用不同形状/内部符号，不能只靠蓝灰颜色区分。

## 5. 视觉规范

### 5.1 定位按钮

- 48×48 px 等效尺寸，圆角 16 px；与搜索框高度一致；
- 白色常态、品牌蓝准星图标、轻量阴影；
- active 使用浅蓝背景和清晰边框；
- loading、active、error 都不改变外部尺寸；
- 不使用 emoji、文字“附近”或不明确的实心圆图形。

### 5.2 搜索栏

- 与定位按钮同高，左侧使用放大镜图标；
- 文案可完整表达“球场或地图地点”；
- 有输入时保留清除入口，但不挤压输入文字；
- 搜索建议使用独立不透明表面，层级高于地图、低于系统导航；
- 键盘打开时保证建议项可见并可安全返回地图状态。

### 5.3 Sheet 与纵向条目

- 默认 `half`、向上 `expanded`、向下 `collapsed`；拖拽之外保留可点按把手与“展开列表/收起地图”替代操作；
- 只有把手和标题区响应 sheet 拖动，列表区的纵向手势只滚动列表；
- 条目间距至少 8 px，触控目标至少 44×44 px；
- 条目使用 16 px 等效圆角；选中状态不得使用缩放动画；
- 大量目录使用纵向滚动，不嵌套横向卡片滚动；
- 进入 `expanded` 后地图仍保留少量上下文，不变成另一个无返回路径的页面。

### 5.4 视觉状态语义

页面不再保留占据地图空间的常驻大图例。状态语义直接附着于场馆标记和每个列表条目；必要时可在首次使用时提供一次性说明，但不能成为永久遮挡地图的控件。

## 6. 数据与权威边界

### 6.1 平台场馆

平台场馆继续由 `GET /api/v1/venues/map` 和现有详情契约提供。腾讯 POI 搜索不能创建、补全、修改或升级平台场馆，也不能提供预订状态、价格、库存或已核验交通信息。

### 6.2 POI 搜索结果

新增前端窄边界：

```ts
type PoiSearchResult = {
  id: string
  name: string
  address: string
  city: string
  district: string
  adcode: string
  latitude: number
  longitude: number
  coordinateSystem: "GCJ02"
}

interface PoiSearchCapability {
  suggest(query: string): Promise<readonly PoiSearchResult[]>
}
```

实施时必须：

- 严格解码第三方响应并丢弃坐标、名称或 ID 不合法的项目；
- 建议项同时显示城市、行政区和结构化地址，消除跨城市同名 POI 歧义；
- 将第三方失败隔离在 POI 建议区域，不污染平台目录状态；
- 不把腾讯 POI 响应写入平台数据库或生产业务 Fixture；
- 不在客户端代码、日志或仓库中暴露不应公开的服务端密钥；
- 明确腾讯位置服务 Key 的应用绑定、调用域名、额度和发布配置；
- 在隐私说明中覆盖用户主动输入的地点搜索和主动定位用途，并披露第三方名称、处理目的、数据类型及适用规则。

用户输入达到触发条件后，搜索词会临时发送至腾讯位置服务以返回地点建议。应用自身不将搜索词、建议结果或所选 POI 发送至业务后端，不持久化、不写入埋点或业务日志。首期 POI 请求不得携带用户当前位置；若未来需要位置偏置，必须另行设计授权与披露。所选 POI 和搜索中心只保存在当前页面会话，首期不做搜索历史或个性化推荐。

## 7. 状态与错误处理

必须覆盖以下独立状态：

- 平台目录首载中、成功、失败与重试；
- POI 建议 idle、loading、ready、empty、error；
- 定位 idle、requesting、ready、denied、error；
- 搜索中心 `CITY | USER_LOCATION | POI`；
- 未提交搜索草稿 `draftQuery` 与进入编辑前的恢复快照；
- sheet `collapsed | half | expanded`；
- 当前选中场馆；
- 筛选后的零结果。

这些状态不能相互误伤：

- 腾讯 POI 搜索失败不卸载地图或平台目录；
- 定位失败完整恢复发起请求前的搜索中心、目录排序、筛选、选中场馆和地图视野；
- 地图底图短暂不可见不触发基于计时器的失败判定；
- 平台目录失败时不能用腾讯 POI 球场冒充业务数据；
- 筛选零结果保留“清除筛选”，而不是显示网络错误。

## 8. 资源与性能预算

- 页面只保留一个原生 `<map>` 实例；
- 场馆列表按纵向轻量条目渲染，实施时验证 50、100 家数据下的真机滚动；
- POI 建议限制可见数量，取消或忽略过期请求，防止旧响应覆盖新查询；
- 距离由纯函数批量计算，不向后端逐场馆请求；
- 搜索结果和列表不得引入未授权远程图片；
- 首期不建设地图移动后自动搜索、实时第三方球场抓取或搜索历史同步。

在 50、100 家 Fixture 上先执行标记可读性和交互性能门槛。若初始全城视野的重叠使目标标记无法可靠点选，或连续地图操作发生超过 200 ms 的可归因输入响应迟滞，则标记聚合或等价密度控制成为本切片上线前置条件。聚合标记只表达数量，不混淆在线预订状态；用户位置和 POI 搜索中心标记始终独立。纵向目录 Demo 可以先行视觉确认，但不得把无法操作的 50+ 标记作为完成状态交付。

`USER_LOCATION` 和 `POI` 的视野计算必须把当前 sheet 高度和未遮挡地图区域纳入偏移，不能简单把搜索中心放在整个 `<map>` 几何中心后再被 sheet 覆盖。

## 9. 前端交付顺序

遵循共享基础优先的单用户旅程切片：

1. 更新 Artifact，制作 `CITY`、`USER_LOCATION`、`POI` 三个 390 px 参考状态；
2. 用隔离 Fixture 实现固定高度纵向列表、定位图标和 sheet 交互；
3. 在 390 px 和 375 px 同尺寸生成参考图、实现图、并排图、50% 叠加图和差异图；
4. 用户明确确认视觉后，冻结 `PoiSearchCapability` 与搜索中心状态契约；
5. 接入腾讯 POI 搜索和真实平台目录；
6. 完成自动化、微信开发者工具和真机验收；
7. 删除搜索与大目录临时 Fixture，并审计生产包无模拟业务数据。

本规格确认不等于视觉验收。只有目标视口的真实运行时 Demo 经用户确认后，才能进入 POI 能力的生产集成。

## 10. 验收标准

### 10.1 视觉与交互

- 定位按钮为清晰准星图标，常态、请求中和成功态尺寸完全一致；
- 任何场馆条目从未选中切换为选中时，外部宽高和相邻条目位置不变；
- 使用当前最长场馆名称、最长地址、两种业务状态和距离文案生成极限 Fixture；内容不与尾部箭头重叠，选中前后尺寸不变；
- 50 家以上场馆使用纵向列表连续浏览，不需要横向滑动寻找；
- 标记选择、列表选择和滚动定位双向同步；
- `CITY`、`USER_LOCATION`、`POI` 三种状态的标题、距离前缀和排序语义正确；
- 在线与目录场馆不只靠颜色区分，目录场馆不出现预订动作；
- 375 px 与 390 px 下无横向溢出、文字遮挡或小于 44 px 的主要触控目标。

### 10.2 搜索与隐私

- 搜索能找到平台场馆名称/地址和腾讯地图 POI；
- 腾讯 POI 在建议中明确标记为“地图地点”；
- 选择腾讯 POI 后只展示平台已收录场馆，并按距 POI 的距离排序；
- POI 搜索失败时平台场馆搜索和全城目录仍可用；
- 未点按定位按钮前不请求位置权限；
- 用户位置、搜索词和所选 POI 不写入应用数据库、埋点或业务日志；
- 网络检查证明搜索词只发往已批准的腾讯位置服务端点，不进入平台 API，且首期 POI 请求不包含用户经纬度。

### 10.3 自动化与设备验收

- presentation 纯函数覆盖三种搜索中心、稳定排序、距离文案和固定状态语义；
- 页面测试覆盖建议请求竞态、清除搜索、定位拒绝、筛选零结果及列表/标记联动；
- 组件测试断言选中前后固定布局类和操作槽位均存在；
- 使用 100 家 Fixture 连续完成列表滚动、20 次标记/列表互选和三种 sheet 状态切换，无错误、错选或超过 200 ms 的可归因输入响应迟滞，并记录设备型号、微信版本和基础库版本；
- 正式发布前至少各一台 iOS 和 Android 真机验证键盘、定位授权、POI 选择、sheet 手势和返回状态保持；
- 构建审计证明生产包不包含临时大目录或 POI Fixture。

## 11. 非目标

- 展示腾讯地图中未被平台收录的球场；
- 实时抓取第三方价格、库存、电话、评分或营业时间；
- 按地图可视范围自动刷新平台场馆；
- 搜索历史、收藏或个性化推荐；
- 服务端空间数据库和半径查询；
- 本次设计确认前修改后端场馆契约。
