# 三类用户与开放球局：关键决策记录

**日期：** 2026-08-09

**用途：** 记录产品节点上的选择、未选方案和理由

| 节点 | 最终选择 | 未选方案 | 主要理由 |
| --- | --- | --- | --- |
| 产品定位 | 真实场地交易之上的足球活动平台 | 单纯订场工具；泛足球社交网络 | 同时连接球场收入、球队成局和散客参与，且能复用现有订单能力 |
| 用户身份 | 一个账号拥有多个场景角色 | 注册时永久选择球场/队长/散客 | 用户角色会随活动变化，永久分型会制造重复账号和权限混乱 |
| 公开球局来源 | 队长必须绑定已支付确认订单 | 先约人、满员再找场地；任何人自由发布 | 保证场地真实，避免人齐后无场、价格变化和垫资争议 |
| 发布权限 | 已支付队长；后续加入审核场馆 | 所有用户自由发布；平台自营所有活动 | 控制虚假供给、客服和安全责任，保留后续官方供给能力 |
| 首期区域 | 只在唯一 `ONLINE` 合作场馆灰度 | 五家目录场馆同时开放；全天津上线 | 拼场依赖供需密度，其余四家没有真实库存，不能作预订承诺 |
| 散客费用 | 展示预计 AA，线下结算 | 平台代收并结算给队长；免费不展示费用 | 透明但不立即引入个人结算、部分退款、提现和税务链路 |
| 年龄 | 公开陌生人球局仅限 18 岁以上 | 成人与未成年人共用流程 | 避免把监护人授权、接送和青少年保护混入首期成人拼场 |
| 顶层入口 | 找球场｜找球局｜我的 | 把球局塞进场地时段页；建立多个独立小程序 | 场地库存与人员名额语义不同，但用户身份和订单应共享 |
| 报名方式 | 散客申请，队长审核 | 有空位即自动加入；算法匹配 | 陌生人首次组局需要组织者控制水平、位置和行为风险 |
| 候补方式 | 空位出现后按 FIFO 自动转正 | 再次人工审核；允许队长手工重排 | 沿用原 PRD 的简单公平规则，并减少空位出现后的二次操作 |
| 退出规则 | 固定为开场前 6 小时；首期只记录不扣款 | 每个队长自定义；收保证金 | 固定规则更易理解，先验证真实爽约率，再决定是否引入资金约束 |
| 信用表达 | 到场事实摘要，少于 3 场显示新球员 | 星级、综合信用分、公开文字评价 | 降低冷启动偏见、报复性评价和算法复杂度 |
| 沟通方式 | 队长公告、报名备注和状态通知 | 陌生人私聊、公开手机号、群聊 | 满足履约所需沟通，同时减少骚扰和隐私泄露 |
| 报名身份 | 微信会话＋18 岁以上声明，不额外收集手机号或身份证 | 公开报名强制手机号；身份证实名认证 | 单场馆灰度遵循最小必要原则，先用真实订单和人工治理控制风险 |
| 订阅消息 | 申请结果、候补转正、取消和开场提醒属于 MVP | 全部依赖微信群；作为 P1 后置 | 陌生人不一定在同一微信群，关键状态必须有可靠的通知尝试 |
| 社交关系 | 从真实到场后逐步形成常客/再次邀请 | 首期建设动态、好友、私信和排行榜 | 真实共同经历比空社交关系更有价值，且实现成本更低 |
| 场馆接入 | 平台审核配置管理员 | 商家自助注册入驻 | 首期只有一家合作场馆，自助入驻会增加审核、权限和结算复杂度 |
| 场馆工作台 | 首期只做库存、价格、今日订单和整场履约 | 同时做完整内容 CMS、经营报表和散客管理 | 保持真实库存所需的最小能力，内容继续由平台协助维护 |
| 场馆官方球局 | 作为后续能力，并要求权威锁场 | 首切片同时实现；允许无场地先发布 | 先闭环队长开放名额，避免同一切片增加另一种库存和组织责任 |
| 排序与推荐 | 单场馆按开场时间排序＋三个简单筛选 | 个性化推荐、水平匹配、复杂地图 | 首期数据量不足以支持算法，清晰和可预期更重要 |
| 成功指标 | 每周真实到场的公开散客席位 | 注册数、浏览量、申请量 | 到场同时验证供给真实性、报名质量和履约价值 |
| 订单与球局 | 一个订单最多一个未取消球局 | 同一订单创建多个活动 | 防止一个真实订单被重复包装成多个公开供给 |

## 与原 PRD 的主要变化

1. 原 PRD 把球局限定为不可猜测链接访问，并明确不做公共球局广场；本方案新增单场馆、受控供给的“找球局”公开目录。
2. 原 PRD 的普通报名不强制手机号；本方案继续保持最小收集，只增加公开陌生人球局的 18 岁以上声明。
3. 原 PRD 没有最小球队对象；本方案增加球队名称、队长和重复开局所需的最小资料。
4. 原 PRD 的报名直接进入正式或候补；陌生人公开报名改为先由队长审核。
5. 原 PRD 把完整体育社交网络列为非目标；本方案仍保持该边界，只允许真实到场后形成轻量复购关系。
6. 开发顺序调整为先补场馆真实运营与订单退款/履约，再做队长开放名额和散客报名，避免球局联动建立在不完整订单状态上。

## 以后再决定

以下节点没有足够真实数据，暂不提前设计：

- 是否需要散客平台内付款或保证金；
- 场馆官方球局采用何种锁场和收费方式；
- 是否需要常客名单、优先邀请或球队关注；
- 是否需要订阅消息增强；
- 是否扩大到更多在线场馆；
- 是否引入保险、商业活动协议或更强年龄核验。

这些决定应由 8 周灰度数据和实际纠纷类型触发，而不是当前预判。
