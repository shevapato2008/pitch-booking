## 1. 目标

本切片让已经持有真实、可用于组局的未来订单的用户，以队长身份开放少量散客名额：

```text
我的订单 / 预订详情
→ 创建球局草稿
→ 设置计划人数、固定队员和开放名额
→ 预览并发布
→ 查看公开详情
→ 分享微信卡片
→ 返回管理页编辑或取消球局
```

订单中的场馆、物理场地和时间是球局真实性来源，不能在球局表单中修改。球局只管理活动内容和人员名额，不重写场地库存、支付或退款状态。

本切片交付的是队长供给侧闭环。散客列表、申请、审核、候补和到场属于 C1/C2；在这些能力真实接入前，公开详情不渲染“申请加入”假按钮，三目的入口“我要找球踢”继续显示“即将开放”。

## 2. 共享前置条件

### 2.1 创建资格

页面只根据服务端权威资格显示“创建球局”，客户端不得自行根据订单文案或本地时钟猜测。创建时服务端还要重新校验：

- 订单属于当前用户；
- 订单状态为 `CONFIRMED`；
- `cancel_requested_at` 为空；
- 没有退款业务单；
- 距离开场严格大于 2 小时；
- 该订单不存在另一条未取消球局。

“距离开场严格大于 2 小时”是本设计发现的共享依赖修正。上游产品规则规定最晚在开场前 2 小时停止新申请；如果只要求订单尚未开场，队长可能创建一个发布即截止的球局。B1 资格纯函数批准前，本切片不得开始 Artifact、Fixture 或实现。

进入创建页后订单可能被取消、退款或被另一设备创建球局，因此保存草稿和发布都必须重新校验，不能依赖进页时的快照。

### 2.2 已有球局的订单联动

- `CONFIRMED` 且无取消/退款流程：草稿可以编辑，已发布球局可以继续招募；
- `REFUND_PENDING`、`REFUND_FAILED`、`PAYMENT_EXCEPTION`：已发布球局进入 `SUSPENDED`，保留内容但暂停新报名；
- `CANCELLED`、`REFUNDED`：球局进入 `CANCELLED`；
- `COMPLETED`：不能新建球局，已有球局只进入赛后只读/到场处理，不重新招募。

订单联动是服务端权威事件。客户端只展示返回的球局状态和允许动作。

## 3. 方案选择

### 方案 A：单页表单＋独立管理页（采用）

- 从订单详情进入一张纵向表单；
- 第一次保存形成私有草稿；
- 草稿管理页承担预览、发布、分享、编辑和取消；
- 公开详情与管理页分离，避免把私有操作暴露给访客。

优点是页面少、字段关系可以在同一屏上下文内理解，同时每个发布后的动作都有稳定去向。

### 方案 B：三步创建向导

把人数、活动要求、发布方式拆成三个步骤。单屏更轻，但会增加返回、草稿恢复、步骤校验和底部按钮状态；当前字段量不值得引入。

### 方案 C：全部内嵌订单详情

开发表面最少，但会混淆“订场订单”和“球局”两个不同领域，也让公开预览、分享和取消球局没有稳定管理页，因此不采用。

## 4. 页面与入口

### 4.1 订单详情入口

在现有订单详情的操作区使用服务端投影决定入口：

- 可创建且没有未取消球局：显示主操作“创建球局”；
- 已有 `DRAFT`、`PUBLISHED` 或 `SUSPENDED` 球局：显示“管理球局”；
- 不可创建且没有球局：不渲染禁用按钮；若用户从过期深链进入创建页，则显示明确阻塞原因并返回订单详情；
- 已取消球局不阻止同一订单在仍满足资格时重新创建一场，仍遵守“最多一条未取消球局”。

“我的订单”卡片继续整体进入订单详情，不新增一排拥挤的小按钮。卡片可以在以后用非交互文字标记“已有球局”，但不作为本切片门槛。

### 4.2 创建 / 编辑页

目标 viewport 为 `375 × 812`，使用单列纵向表单。页面顺序：

1. 自定义或原生导航标题“创建球局” / “编辑球局”；
2. “真实订场已确认”订单摘要卡；
3. 球局与球队；
4. 人数与开放名额；
5. 强度、经验和位置需求；
6. 预计 AA 和固定的线下结算说明；
7. 报名截止、装备和到场说明；
8. 可见范围；
9. 尊重底部安全区的固定主操作“保存草稿” / “保存修改”。

订单摘要只显示场馆、物理场地、日期、起止时间和场地规格，不显示手机号、支付流水或订单内部状态字段。场馆、场地、时间均标记“来自已确认订单，不可修改”。

### 4.3 球局管理页

保存草稿后进入管理页，而不是直接公开。管理页从上到下显示：

- 状态徽标和一句真实说明；
- 场馆、场地、时间的订单真实性卡；
- 固定人数、开放名额、预计 AA、强度和可见范围摘要；
- 公开详情预览；
- 当前状态允许的操作。

动作按状态闭合：

| 状态 | 主操作 | 次操作 |
| --- | --- | --- |
| `DRAFT` | 发布球局 | 预览、编辑、放弃草稿 |
| `PUBLISHED` | 分享球局 | 查看公开页、编辑、取消球局 |
| `SUSPENDED` | 查看原因 | 查看公开页、取消球局；不允许重新发布或分享招募 |
| `CANCELLED` | 无 | 查看取消结果、返回订单 |
| `COMPLETED` | 无 | 查看公开页；赛后到场处理留给 C2 |

所有可见按钮都必须有真实行为。不可用动作不渲染成灰色按钮，改为普通说明文字。

### 4.4 公开详情

公开详情沿用已有开放球局概念稿的信息顺序，但本切片只提供真实只读内容：

1. “真实订场已确认”及日期、时间、场馆、物理场地；
2. 固定人数、开放人数和计划总人数；
3. 对抗强度、最低经验和位置需求；
4. 预计人均费用，以及“到场线下结算，平台不代收或担保”；
5. 球队 / 组织者的最小展示身份；
6. 报名截止、装备和到场说明；
7. 成人、退出和运动风险规则。

B2 尚未接入散客申请，因此页面底部显示非交互说明“当前仅供查看，申请加入即将开放”，不显示可点击 CTA。C1 接入真实申请后再替换为服务端权威的申请动作。

公开页不返回或展示订单编号、队长手机号、微信号、完整成员名单、报名备注或支付字段。

## 5. 表单字段与约束

### 5.1 球局和球队

- 球局名称：必填，2–30 个可见字符；默认可以由“球队名称＋日期”生成，队长可修改；
- 球队名称：必填，2–24 个可见字符；首次创建时同时形成最小球队资料；
- 本切片不建设球队名册、队徽、转让队长或球队管理页；以后存在历史球队时可以预填最近使用的名称，不阻塞当前表单。

### 5.2 人数和开放名额

- 计划总人数：使用步进器，范围 4–30；已知五人制默认 10、七人制默认 14，默认值只是输入辅助，不是场地容量权威；
- 已有固定队员：使用步进器，包含队长本人，最小 1；
- 开放给散客：使用步进器，最小 1，最大为 `计划总人数 - 已有固定队员`；
- 允许开放名额少于剩余容量，表示仍为可能到场的固定队员预留位置；页面明确显示“计划共 X 人，当前固定 Y 人，本次开放 Z 个名额”；
- 不接受只有颜色或数字变化的隐式反馈，越界时在步进器下方说明原因。

C1 有散客加入后，后续编辑必须满足：开放容量不低于已加入散客人数，计划总人数不低于固定队员和已加入散客之和。

### 5.3 强度、位置和说明

- 对抗强度：单选 `新手友好 | 休闲对抗 | 认真对抗`；
- 最低经验说明：可选，最多 60 个字符；
- 位置需求：多选 `门将 | 后卫 | 中场 | 前锋 | 位置不限`，“位置不限”与其他项互斥；
- 装备和到场说明：可选，最多 200 个字符，不承担私聊或公开联系方式功能。

### 5.4 费用、截止和可见范围

- 预计人均 AA：必填，人民币元输入，允许 0；订单金额除以计划总人数只作为辅助建议，不自动覆盖用户输入；
- 已有散客加入后，预计 AA 只能保持或降低，不能提高；
- 报名截止：默认开场前 2 小时，只允许选择当前时间之后、且不晚于开场前 2 小时的时间；
- 可见范围：`PUBLIC` 表示未来可以进入公开列表，`LINK_ONLY` 表示只通过分享链接访问；两者都公开相同的脱敏详情，并在 C1 使用相同申请审核规则。

字段使用可见标签，不用 placeholder 代替标签；数字字段使用数字键盘。普通字段在失焦时就地校验，跨字段关系在任一相关步进器变化后立即更新，提交失败时同时在字段旁和页面顶部给出可理解摘要。

## 6. 发布、分享、编辑和取消

### 6.1 草稿与发布

- “保存草稿”只创建队长可见的 `DRAFT`，不出现在公开列表，也不能分享；
- 发布前显示一页内预览和确认项：真实场地、开放名额、预计 AA、线下结算、截止时间、可见范围；
- “确认发布”成功后进入 `PUBLISHED` 管理页；
- 发布请求超时不能直接显示成功或失败，保留草稿并进入“正在确认发布结果”，使用同一次操作标识重新读取结果；
- 资格变化或重复球局冲突时保留草稿内容，说明阻塞原因；若服务端返回已有球局，则直接进入对应管理页。

### 6.2 分享卡片

只为 `PUBLISHED` 球局提供微信原生分享：

- 标题使用球局名称和时间，不包含手机号或招募夸张承诺；
- 图片优先使用已审核通过的场馆封面；没有可公开图片时使用产品默认品牌图，不临时生成位图；
- 路径进入该球局的公开详情；`LINK_ONLY` 使用不可枚举的分享标识，不暴露订单 ID；
- 分享面板打开失败只说明“暂时无法分享”，不改变球局状态；
- 分享次数不作为发布成功或业务状态依据。

### 6.3 编辑

- `DRAFT` 可以编辑全部球局字段，订单摘要永远只读；
- `PUBLISHED` 可以编辑非订单字段；C1 接入后遵守人数和费用不可逆约束；
- `SUSPENDED`、`CANCELLED` 和 `COMPLETED` 本切片只读；
- 保存中禁止重复提交；结果未知时保留输入并重新读取，不回滚成旧内容，也不显示假成功。

### 6.4 取消球局

“放弃草稿”或“取消球局”都必须二次确认，确认文案明确：

> 只取消本次开放球局，不会取消已预订场地，也不会发起退款。

本切片没有散客报名，因此取消可以直接进入 `CANCELLED`。C1 接入后，同一动作还要取消待处理与已加入报名并触发通知尝试，但通知失败不能回滚球局取消。

取消结果未知时管理页显示“正在确认取消结果”，禁止重复创建或重新发布，直到服务端返回权威结果。

## 7. 页面状态和错误语义

创建 / 编辑页至少覆盖：

- `LOADING_ORDER`：稳定骨架，不展示可编辑的假字段；
- `READY`：权威订单摘要和本地表单；
- `INELIGIBLE`：说明订单不可用于创建，并提供“返回订单”；
- `SAVING`：保留输入、禁用重复提交；
- `SAVE_ERROR`：保留输入，字段错误就地显示；
- `SAVE_UNKNOWN`：保留输入并确认原操作结果。

管理页至少覆盖：

- 加载失败及真实“重新加载”；
- `DRAFT`、`PUBLISHED`、`SUSPENDED`、`CANCELLED`、`COMPLETED`；
- 发布、编辑、取消的提交中和结果未知；
- 权限失效时退出编辑能力，但不泄露其他用户草稿。

公开页至少覆盖：

- loading；
- ready；
- 暂停报名；
- 已取消；
- 已结束；
- 链接不存在或已失效。

401 只沿用现有一次微信重新登录后重试；仍失败时保留可理解错误。资源不存在和无权访问私有管理页使用相同的不存在表现，不能泄露球局或订单是否属于他人。

## 8. 视觉系统

工具建议的黑金、超大营销字体和滚动动画不适合既有小程序，明确不采用。复用已经确认的产品设计系统：

- 背景 `#F8FAFC`；
- 表面 `#FFFFFF`；
- 主文字 `#10243E`；
- 次要文字 `#526479` / `#64748B`；
- 边框 `#DBE5EC`；
- 可信蓝 `#0284C7`，深蓝操作文字 `#0369A1`；
- 场地已确认 / 发布成功使用通过对比度检查的语义绿；
- 错误和破坏性操作使用既有语义红，并同时显示文字；
- 系统字体、4/8px 间距节奏、最小 44pt 触控区域。

按钮和步进器使用显式 flex 双轴居中，不能只依赖固定高度或默认 `line-height`。同组步进按钮尺寸一致，图标使用同一套线性矢量风格，不使用 emoji。固定底栏为滚动内容预留底部空间，并包含 iPhone 底部安全区。

页面动效只保留 150–300ms 的按压和底部确认面板过渡；不加入装饰性滚动动画。破坏性确认面板提供清晰关闭操作，遮罩足以隔离背景。

## 9. Artifact、Fixture 与视觉门槛

B1 订单资格规格批准后，才进入下一阶段：

1. 为 `375 × 812` 制作创建页、草稿管理页、已发布管理页和公开详情参考 Artifact；
2. development-only Fixture 覆盖 eligible、ineligible、draft、published、suspended、cancelled、save-unknown；
3. 所有按钮在 Fixture 中有可验证状态转换，不使用静态 Toast 冒充行为；
4. 在同一 viewport 生成参考图、真实原生实现图、并排图、50% 叠加图和差异图；
5. 先人工检查文字双轴居中、步进器对齐、底部安全区、长文案换行、键盘顶起和所有按钮点击结果；
6. 用户视觉确认后才冻结球局契约和开发生产后端。

生产包不得包含队长资格、球局发布成功或公开详情的模拟业务数据。development Fixture 的删除条件是生产创建、保存草稿、发布、分享、编辑、取消和公开详情全部通过聚焦自动化与真机验收。

## 10. 最小验收

视觉阶段：

- 队长能从 eligible 订单进入创建页，ineligible 订单没有假入口；
- 人数步进器和开放名额约束可理解，错误紧邻字段；
- 保存草稿、发布、分享、编辑和取消均有明确可操作状态；
- 公开详情没有申请假按钮，也没有暴露订单或联系人隐私；
- 375×812 上固定底栏、微信胶囊、键盘和底部安全区不遮挡内容。

后续生产阶段：

- 同一订单并发创建最多产生一条未取消球局；
- 保存和发布时都重新校验 B1 权威资格；
- 订单异常、退款、取消和完成能把球局投影到正确状态；
- `PUBLIC` 与 `LINK_ONLY` 的发现范围不同，但公开详情隐私边界一致；
- 取消球局不修改订单、支付、退款或场地库存；
- production 构建不含 Fixture，所有可见按钮都有真实行为。

## 11. 明确不做

- 散客申请、队长接受 / 婉拒、候补和订阅消息；
- “找球局”公开列表和三目的散客入口启用；
- 散客平台内 AA、保证金、钱包、分账或队长提现；
- 队伍名册、队徽、聊天、动态、评分和复杂信用体系；
- 场馆官方球局；
- 复制球局、周期球局、推荐算法或跨城市发布；
- 自定义分享海报或服务端图片生成；
- 在 B1 资格规格批准前生成截图、实现 Fixture、修改契约或开发生产后端。

## 12. 并行边界

本设计文档可以和 B1 生命周期规格审查并行完成。除此以外：

- B1 资格纯函数和订单状态联动由共享基础任务串行拥有；
