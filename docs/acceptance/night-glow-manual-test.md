## 2. 准备与通用视觉检查

本轮优先检查（约 5 分钟）：

1. 从首页依次进入“我要出租场地 / 我要租赁场地 / 我要找球踢”。三个模块左上角应是同尺寸白色线框小房子，位置一致，点击均回目的首页。
2. 进入“我的报名”、场馆详情、时段等二级页面。左上角统一为返回箭头，原返回目的地和未保存提醒不变；长标题不压住微信胶囊。
3. 打开库存编辑层但不保存，检查 X 完整、取消和保存等高且文字居中；点击 X/取消能关闭。不要用真实经营时段测试写入。
4. 地图输入搜索内容，检查清除 X 与“取消”均在一行，搜索建议盖住下方快捷入口而非被遮挡；取消后恢复原地图状态。
5. 检查筛选已选态、不可修改但已选的选项、主次按钮、危险操作和状态徽标。相同用途应同风格，禁用不等于隐藏已选值，危险与主操作不可混淆。

先用一台常用手机完成主旅程（约 20 分钟）。建议先在 390 × 844 逻辑尺寸的开发者工具中检查，复杂表单再补一台较窄屏幕或另一系统设备；无需为每次颜色调整重拍所有状态。

基础浏览不要求管理权限。深度业务检查需普通球员账号、队长账号及已有授权的场馆工作人员账号；只使用专用测试球局/场馆。保存、报名、退出、举报、库存编辑等会调用真实后端，不要对真实客户数据做破坏性测试。

每个代表页面都看这几项：

- 主按钮青柠底配深色字，正文清晰；警告、候补、危险和禁用状态不能只靠相近颜色区分。
- 按钮文字水平与垂直居中；同组状态徽标等高、同列对齐。
- 返回箭头、下拉箭头、关闭 X、勾选和锁形图标完整，无缺边或裁切。
- 顶部不侵入状态栏/微信胶囊；固定底栏不盖正文或 Home 指示条。
- 长场馆名、日期、金额、AA 说明和报名截止时间不相互挤压；可滚动内容能到达末尾。
- 首次出现和弹层只有短过渡；连续点击、返回、滚动时不反复闪烁，不出现无限装饰动画。

## 4. 找球踢与报名：重点视觉旅程

1. 首页 → 我要找球踢。检查球场光影、标题、发现球局/我的报名入口、日期条和人制筛选；横向日期条不能带动整个页面横向溢出。
2. 切换日期、人制、“仅看有名额”。结果数、余位和当前筛选应一致；无匹配时点清除筛选应恢复。当前后端无公开球局时只检查真实空态，不临时向线上注入样板数据。
3. 点击真实球局整张卡片。详情应与列表的名称、时间、场馆、人制一致；AA 费用、到场线下结算、报名截止、人数和候补不能因新布局丢失。
4. 未登录/未报名视角查看名单区。应保留名单隐私说明，不能显示未经授权的成员信息。
5. 用测试球员在允许报名的测试球局打开报名资料层。检查昵称、头像入口、勾选、关闭/确认按钮，以及键盘弹出后能否操作底部按钮；先取消一次，确认不会报名。
6. 如需要真实报名验收，再按页面要求填写资料并确认。只有后端确认后才显示成功状态；返回“我的报名”并重新进入，应读回一致结果。重复快速点击不得产生多条报名。
7. 有正式成员/候补测试数据时分别查看详情：正式状态、候补位置/人数、可用动作和名单权限应一致。打开退出/撤回确认层先取消，状态不能变化；确需测试退出时使用测试记录并重新进入核对结果。
8. 检查报名编号复制（有该入口时）；粘贴到本地输入框核对。举报入口仅检查表单与取消；除非有专门测试安排，不提交虚假举报。

此包未启用候补微信通知，不把“未收到微信提醒”当作本次视觉改版缺陷；页面仍必须以服务端实际报名状态为准。

## 5. 队长旅程：有测试球局时进行

入口为已有合资格订单/球局的管理页，不要求为本次 UI 验收创建真实付费订单。

- 球局表单：检查名称、人数、位置、AA、截止时间等字段；输入长内容后观察换行和错误提示。保存会写真实数据，使用测试球局。
- 管理页：查看公开页、编辑球局、报名审核、成员管理、散客到场记录只应在服务端允许时出现。打开发布/取消确认层再返回，不能产生状态变更。
- 报名审核：多行重复按钮/徽标应同列对齐；申请满额时不应因样式出现错误的可接受动作。真实同意/候补/拒绝操作只对测试球员执行，并由球员端刷新核对。
- 成员管理：头像/昵称和移出等危险按钮应清晰；确认层可取消，不能只弹 Toast 就当作完成。
- 到场记录：检查到场/未到场按钮、确认层、编号复制和已记录只读状态。此类记录影响真实历史，只用专用测试记录；已有纠正信息应正确显示。

## 7. 轻量异常检查与反馈

完成主旅程后，在一个只读列表做一次断网重载、恢复网络后重试；观察错误提示可读、重试能恢复、无假成功。不要在真实支付或真实资料提交过程中人为断网。

发现问题时记录：手机型号/系统/微信版本、入口和页面、操作步骤、期望/实际、截图或短录屏、是否稳定复现。截图请遮盖手机号、邀请链接、个人资料及不必要的订单/报名标识。

建议按三档反馈：阻断（白屏、点不了、状态错误）、明显视觉问题（文字裁切/低对比/遮挡）、风格偏好（留白、字号、动画强弱）。优先修前两档，再集中调整风格。
